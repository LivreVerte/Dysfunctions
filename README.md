# Dysfunctions
The code for the Keep Talking and Nobody Explodes moded module Dysfunctions. 
The module is a puzzle module in which you query base 6 inputs into it and then observe the output, while a metafunction changes the function each time and there are restrictions on the queries. 
My thought process on each component is as follows. I have said previously that one of the primary goals of the module is to make it as hard as possible to make a Look Up Table for it, and thus came the systems the module uses. 
The reason it changes functions is because if it didn't, it would be easy to simply find a set of queries that gives a unique value for each function, especially with many functions giving large numbers and no edgework required. This incentive to query several times is also what makes the restrictions so restrictive. 
The restrictions were put in place to, well, restrict the queries. With unlimited queries, it would only take the same query several times in a row to disambiguate the function, even with the metafunction. The restrictions are put in place to make it so you cannot do the same query multiple times in a row, or find a set of queries that work. While that is still possible, with 68 different restriction possibilities, with the factors starting at 6 possible orientaitons for each one makes it significantly more difficult. If you are willing to strike to solve the module faster, be my guest, that seems an appropriate punishment for the unrestricted queries it offers. 
The final addition to the result of the submission query is an anti yolo method. There are only 36 functions, it would be easy to take the result of one of the methods each time and try again and again until it gets that method to start and submit the result. With the addition, this becomes less likely to succeed, as the 36 possible metafunctions make there be 1296 possible results, excluding duplicates. If you are still crazy enough to yolo it, go for it, there is nothing I can do to stop you from brute forcing that. 

In terms of the systems themselves: There is the unity file that I will attach in this repo, as well as the code. The code itself is mostly done in Java as that is what I am familiar with and copy+pasted into C# with minimal changes. The top of the code is all of the globals, and then is the handling of the user's actions. Most of the code is in the function that handles the button presses. The final submission is in a function called Delay. I will be the first to admit that the optimization in that code is terrible, and there are a lot better ways to do it, but from what I can tell it all works. 
The Unity File itself has most of its stuff from the KModKit. The buttons are from a Custom Assets pack made by Ash the Bash, and most of the cyan tubes are made from Unity cylindars.
